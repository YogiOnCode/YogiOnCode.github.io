Context

The problem

Working with AI coding agents means running four or five sessions at once, each in its own terminal. One is waiting for a permission, one finished ten minutes ago, and you're in the browser.

A session stuck on a permission prompt does nothing until you notice. The cost isn't the agent's time, it's yours: switching windows to check.

Goal: one window for every session, and a signal that reaches you wherever you are, without interrupting what you're doing.

The island: it drops in when a session needs you and never takes keyboard focus.

Key decisions

The tradeoffs that shaped it

Written as short architecture decision records: what the situation was, what I chose, and what it cost.

ADR-01Host the real terminal, don't rebuild a chat UI

Context
The agents can be driven as a stream of JSON messages and rendered in a native, prettier chat view.
Decision
Embed the genuine terminal (ConPTY + xterm.js) and put the polish into everything around it.
Tradeoff
A terminal in a box never looks as designed as a native view. In exchange, slash commands, permission prompts, plan mode and the status line keep working, including future features of the CLI.

ADR-02Clayo owns the branch graph

Context
Nothing in the agents' transcripts records which session a fork came from.
Decision
Pre-allocate the child session's ID before launching it, and persist the parent→child edge in one small JSON file.
Tradeoff
One more file to keep in sync, but it's the piece that makes the session tree possible at all.

ADR-03Notify without interrupting

Context
A notification that grabs focus breaks your typing; a hidden "hot strip" at the top of the screen covers the browser's tab bar.
Decision
A no-activate tool window, no window at all while hidden (the cursor position is polled instead), stays quiet during fullscreen and presentations.
Tradeoff
A cheap poll instead of an event, slowed to 250 ms when the cursor is away from the top edge.

ADR-04Don't kill everything a pane started

Context
A Windows job object would clean up every child process when a pane closes.
Decision
Dropped it. Console children already exit with the pane, as in Windows Terminal.
Tradeoff
Less aggressive cleanup, but closing a pane no longer kills an editor you opened from it with code .

ADR-05Integrity now, code signing later

Context
Code-signing certificates cost money and take time; an unsigned download is still a real risk.
Decision
Ship SHA-256 checks and GitHub build attestations now; add Authenticode via a free open-source signing program later.
Tradeoff
Windows SmartScreen still warns on first run until signing lands.

Security

The pre-launch audit

Before posting it publicly, I audited Clayo for security and memory issues and fixed them in one release.

RiskFix
Tampered download or update
→
SHA-256 + build attestation, checked before unpackingUpdates are fetched from the release tag, not the main branch.
Malicious link in terminal output
→
Web view locked to its own pageLinks go through a confirm step and open in your real browser.
Untrusted IDs, paths and git config
→
Quoted everywhere; risky git hooks offA repo can't make Clayo run its code just by being opened.
Crash or leak when a pane fails
→
Isolated panes, handles releasedA failing pane can't take the app down or leave a shell behind.
Unbounded files on disk
→
Pruned and rotatedStatus files older than 7 days are removed; the crash log rotates at 1 MB.
